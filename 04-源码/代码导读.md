## 二、运行时：`Play.lua` 是个状态机调度器

所有战术脚本用 `gPlayTable.CreatePlay{ name=..., firstState=..., ["状态名"]={switch=..., 角色=task } }` 注册进全局表。每帧 `Run_Play(play_name)` 做三件事：

1. 若换了 play，重置到 `firstState`；
2. 调当前状态的 `switch()`，返回下一个状态名（或 `"finish"`）；
3. 对新状态里的每个角色执行对应 `task()`——task 是闭包，最终落到 C++ 侧的 `CKicker_Skill` / `CGetBall` / `CGotoPos` 等绑定。

一个最小的真实例子（`6P_LUA/P_Penalty.lua` 全文）：

```lua
gPlayTable.CreatePlay{
firstState = "PenaltyKick",
["PenaltyKick"] = {
switch = function()
if CIsBallKick("Kicker") then
return "finsh"          -- 注意：拼写是 finsh，不是 finish
end
end,
Kicker = task.KickerTask("dianqiu"),
Receiver=task.GotoPos("Receiver",50,150,0),
Goalie = task.Goalie()
},
name="P_Penalty"
}
```

点球一轮就一个状态：3 号用 `dianqiu.dll` 直接射，5 号让开去 (50,150)，1 号守门。`switch` 只在球被踢出后返回，其余时间保持该状态。

## 三、五个点位的战术脚本

同一套三段式：**拿球 → 传球 → 射门**，对应状态 `GetBall → PassBall → Shoot`。

```lua
["GetBall"] = {
switch = function()
    if Cbuf_cnt((CBall2RoleDist("Receiver") < 30 and CRole2TargetDist("Kicker") < 5), 120) then
        return "PassBall"
    end
end,
Kicker   = task.GotoPos("Kicker", 80, 5, KickerRole2BallDir),
Receiver = task.GetBall("Receiver", "Kicker"),
},
```

- `Cbuf_cnt(条件, 120)`：条件成立并**持续 120 帧**才切换状态，避免一帧抖动就跳；
- `CBall2RoleDist("Receiver") < 30`：球到 5 号 30 以内；`CRole2TargetDist("Kicker") < 5`：3 号已到 (80,5) 5 以内；
- `task.GetBall("Receiver","Kicker")`：5 号朝 3 号方向拿球（两个参数相同则朝球门）。

### 五个脚本的实际差异（`6P_LUA/`）

| 脚本 | 状态 | Kicker 起始位 | 传球技能 | 射门技能 | 备注 |
| --- | --- | --- | --- | --- | --- |
| `P_Back.lua` | GetBall→PassBall→Shoot | (80, 5) | `chuanqiu` | `shemen` | 后场 |
| `P_Corner.lua` | 同上 | (80, 5) | `chuanqiu` | `shemen` | 与 P_Back **仅 name 不同** |
| `P_Front.lua` | 同上 | (80, 5) | `chuanqiu` | `shemen` | 与 P_Back **仅 name 不同** |
| `P_Middle.lua` | 同上 | (130, 5) | `chuanqiu` | `shemen` | Kicker 起始位往右挪 50 |
| `P_Penalty.lua` | 单状态 PenaltyKick | — | 无 | `dianqiu` | 点球允许直接射 |

传球后 3 号不动（`task.RobotHalt("Kicker")`），5 号用 `chuanqiu.dll` 出球；接到球后 5 号退到 `(-176, -178)` 让开，3 号用 `shemen.dll` 射门。

### `K_*` 系列（后来的重写版，`7K_LUA/`）

`K_Back / K_Corner / K_Front / K_Penalty` 是 7 月底之后重写的一版，状态更细（`start1 → passball → receive → shoot`），并且真正按**球在左半场还是右半场**做镜像：

```lua
local TY = function()
    return function()
        local res
        if CGetBallY() >= 0 then res = 148 else res = -148 end
        return res
    end
end
```

`K_Corner` 把接球点定在 ±35 / ±148，`K_Front` 用 `ff(role)` 按机器人自身 y 的正负给 ±150、3 号跑 x=250。技能换成了 `KG2/KP2/KR1/KS/KW1/KW2` 这批新 DLL。

## 四、Lua 怎么调到 C++ 技能 DLL

`skill/KickerSkill.lua` 把 Lua 侧的表摊成位置参数，交给绑定函数：

```lua
if task.kp ~= nil then kp = task.kp else kp = 127 end   -- 默认踢球力度
if task.cp ~= nil then cp = task.cp else cp = 6   end
CKicker_Skill(name, posX, posY, dir, kickflat, kp, cp)
```

`name` 直接对应 `Team/user_skills/<name>.dll`。所以：

| Lua 里写的 | 加载的 DLL |
| --- | --- |
| `task.KickerTask("shemen")` | `user_skills/shemen.dll` |
| `task.KickerTask("dianqiu")` | `user_skills/dianqiu.dll` |
| `task.ReceiverTask("chuanqiu")` | `user_skills/chuanqiu.dll` |
| `task.KickerTask("KG2")` / `"KP2"` / `"KS"` | `KG2.dll` / `KP2.dll` / `KS.dll` |

`user_skills/` 里共 33 个 DLL（提交版是 22 个）。名字前缀能看出用途：`K*` 是 Kicker 系（`KG1/KG2/KGo/KP1/KP2/KR1/KR2/KS/KW1/KW2`），`my*` 是自写的主力技能（`mypass`、`myshoot`、`myget1`、`mypass_gf`…），`chuanqiu/dianqiu/shemen` 是后来按中文重命名的版本。。

## 六、代码里的几个问题（留着别改，但要知道）

1. **`Cbuf_cnt(ture, 120)` 拼错成 `ture`**，出现在 `6P_LUA/P_*.lua` 和 `Package/BackDef/P_*.lua` 共 10 处。`ture` 是 `nil`，这个"超时兜底"实际永远不会触发——P_ 系列的 PassBall→Shoot 只靠 `CIsBallKick` 或球到 5 号 5 以内来推进，一旦 5 号踢空就会卡在这一状态直到 15 秒用完。这正好对应技术报告里"传球踢空"的问题，`7K_LUA` 的 K_ 系列（用 `Cbuf_cnt(CBall2RoleDist("Receiver")<20, 20)`）是修过的写法。
2. **后场/前场/角球三个脚本除了 `name` 完全一样**，Kicker 都站 (80,5)，没有按点位分别标定。中场是唯一改了坐标的（130,5）。所以角球点位实际跑的是后场那套动作。
3. **魔法数字散落**：坐标 (80,5)、(-176,-178)、(50,150)、阈值 30/5/20、`kp=127`、`cp=6` 都硬编码在脚本里，没有集中配置。
4. **`play/Test` 与 `play/Package` 76 组内容完全重复**（见下）。
